# Go 1.27 HTTP Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Register `/stream/` with a Go 1.27 `ServeMux` remainder wildcard and use `Request.PathValue` for canonical stream IDs without changing the existing request, redirect, lookup, or response contract.

**Architecture:** Characterize the current methodless subtree route and `Stream` handler before changing production code. Centralize wildcard registration, then read the decoded wildcard for canonical origin-form requests while retaining the legacy `RequestURI` lookup only as a compatibility fallback for queries, forced empty queries, escaped spellings, and absolute-form request targets.

**Tech Stack:** Go 1.27.0, `net/http`, `net/http/httptest`, vendored modules, standard `testing` package.

**Spec:** `docs/superpowers/specs/2026-08-26-go-1.27-modernization-design.md`

## Global Constraints

- Run every command from the repository root.
- The module remains at `go 1.27.0`; add no dependencies and do not modify `go.mod`, `go.sum`, or `vendor/`.
- Preserve supported platforms, external APIs, persisted formats, and existing error behavior unless a separately approved contract change says otherwise.
- Keep the route methodless: GET, HEAD, POST, PATCH, and other methods must continue reaching `Stream` rather than receiving a mux-generated `405`.
- Preserve the raw lookup behavior for queries, an empty `?` (`URL.ForceQuery`), escaped path spellings (`URL.RawPath`/`URL.EscapedPath`), and absolute-form `RequestURI` values.
- Preserve Go 1.27 mux redirects: `/stream`, repeated slashes, and dot segments receive `307 Temporary Redirect`, not `301 Moved Permanently`; the root redirect preserves its query in `Location`.
- Preserve `/stream/` empty-suffix handling, nested suffix handling, trailing-suffix-slash handling, unknown-ID handling, successful redirect headers, upstream HEAD headers, and `httpStatusError` responses.
- Do not alter the other registrations in `StartWebserver`; `/stream/{streamID...}` has been checked against every current pattern and introduces no `ServeMux` conflict.
- Do not modernize `Auto` or any unrelated `RequestURI` parsing.
- Do not enable h2c or change supported HTTP protocols.
- `http.CrossOriginProtection` remains deferred. Do not construct or register it, wrap the mux or server with it, add trusted-origin configuration, or change Host/Origin/reverse-proxy behavior.
- Do not use `t.Parallel`; the characterization test temporarily replaces package globals.
- Keep commits small, independently testable, reviewable, and easy to revert.

## Verified Current State

- `src/webserver.go:23-66` defines `StartWebserver() (err error)` and currently registers `http.HandleFunc("/stream/", Stream)` on `http.DefaultServeMux`.
- The complete first-party route inventory is `/`, `/stream/`, `/xmltv/`, `/m3u/`, `/data/`, `/web/`, `/download/`, `/api/`, `/images/`, `/data_images/`, `/ppv/enable`, `/ppv/disable`, and `/auto/`. Replacing only `/stream/` with `/stream/{streamID...}` is conflict-free; `/` remains the less-specific fallback.
- `src/webserver.go:143-246` defines `Stream(http.ResponseWriter, *http.Request)`. It currently computes the cache key with `strings.Replace(r.RequestURI, "/stream/", "", 1)` and passes it to `getStreamInfo`.
- `src/system.go:370-394` defines `getStreamInfo(urlID string) (streamInfo StreamInfo, err error)`. Keeping the same fallback key preserves cache loading, lookup, and error behavior for noncanonical requests.
- `src/webserver.go:1240-1242` defines `httpStatusError(http.ResponseWriter, *http.Request, int)`; a stream miss produces status `404` and body `Not Found [404]\n`.
- Go 1.27 matches a `{name...}` wildcard at the empty subtree root and across nested suffixes. `Request.PathValue` returns the decoded, query-free remainder; it therefore cannot by itself reproduce the old raw `RequestURI` key.
- Go 1.27 performs trailing-slash and clean-path redirects before invoking `Stream`, using status `307`. A methodless pattern matches every method; only `HEAD` receives special handling inside `Stream`.

## Final Route Contract

| Request | Expected result |
|---|---|
| `GET /stream/{known canonical ID}` | `302`, upstream `Location`, CORS `*`, HTML redirect body with the URL HTML-escaped |
| `HEAD /stream/{known canonical ID}` | `200`, copied upstream HEAD headers |
| `POST` or `PATCH /stream/{known canonical ID}` | `302`, upstream `Location`, CORS `*` |
| GET/HEAD/POST with an unknown canonical-looking ID | `404` |
| `GET /stream/` | `404` |
| `GET /stream` | `307`, `Location: /stream/` |
| `GET /stream?token=abc` | `307`, `Location: /stream/?token=abc` |
| Repeated slash or literal dot-segment paths | `307` to the clean path |
| Known ID followed by `/segment.ts` or `/` | `404` |
| Percent-escaped spelling of the route prefix or known ID | `404` |
| Escaped slash in the suffix | `404` |
| Known ID with `?token=abc` | `404` |
| Known ID with an empty `?` delimiter (`ForceQuery == true`) | `404` |
| Absolute-form target containing a known ID | `404` |

Threadfin-generated stream IDs are canonical lowercase MD5 hex strings. The compatibility fallback is nevertheless exact rather than assuming every incoming request uses origin form: removing `RequestURI` entirely would turn escaped, query-bearing, or absolute-form legacy misses into successful lookups.
