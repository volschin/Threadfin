# Go 1.27 Safe API Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Modernize Threadfin's first-party Go code with the reviewed, behavior-preserving Go 1.27 language and standard-library APIs in Workstream 1 only.

**Architecture:** Apply each modernization as a narrowly scoped, independently reviewable refactor. Analyzer-supported changes use an individual `go fix -diff` analyzer as the red/green contract; collection and parsing changes first add focused characterization tests and a source-pattern red check. Public APIs, persisted formats, ordering policies, and error behavior remain unchanged.

**Tech Stack:** Go 1.27.0; standard-library `errors`, `maps`, `reflect`, `slices`, `strings`, and `testing`; vendored module resolution.

**Spec:** `docs/superpowers/specs/2026-08-26-go-1.27-modernization-design.md`

## Global Constraints

- Run every command from the repository root.
- All line ranges are 1-based and refer to commit `e7b1c9348c9af94515b39122fbdbd72104c11763`.
- Keep the `go 1.27.0` directive in `go.mod` unchanged.
- Modify first-party Go code in the repository root and `src/` only; do not modify `vendor/`.
- Preserve Linux (`amd64`, `arm64`, `arm`), FreeBSD (`amd64`, `arm`), macOS (`amd64`, `arm64`), and Windows (`amd64`) support.
- Preserve external APIs, persisted formats, output ordering, and existing error behavior.
- Preview each accepted `go fix` analyzer independently; never apply the complete `go fix` output.
- Do not replace `interface{}` with `any`, including nearby or test-only occurrences.
- Do not accept incidental `maps.Copy`, `strings.Builder`, `omitzero`, `new(expr)`, or unrelated analyzer findings.
- Do not use `slices.Backward` in loops that mutate the traversed slice.
- Do not use `clear` where replacing a map changes identity or releases capacity.
- Do not use `slices.Clone` in production where nil versus non-nil empty slices can affect serialized state.
- Do not make broad `sort`-to-`slices.Sort` spelling changes.
- Do not introduce generic methods, generic aliases, custom iterators, `unique`, concurrency redesigns, JSON v2 defaults, HTTP routing changes, h2c, serialization-tag changes, or PGO.
- Do not claim performance improvements for these source refactors.
- Keep every task commit independently testable and revertible.
- Before each commit, run `gofmt` on every touched Go file and run the focused tests named by that task.

func parseGroupCountLabel(label string) (name string, count int, ok bool) {
