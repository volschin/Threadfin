# Go 1.27 Serialization and Streaming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce JSON, XMLTV, image, and segment allocation pressure while preserving persisted formats, HTTP contracts, and observable I/O failures.

**Architecture:** Workstream 4 consumes the helper seams and deterministic benchmarks owned by Workstream 2. JSON v2 reader decoding is isolated behind v1-compatible options; XMLTV retains its manual root format while reusing one encoder; images and segments stream through focused helpers without changing route ownership or writing a second HTTP status after commitment. Every performance candidate is compared with an immutable prerequisite worktree.

**Tech Stack:** Go 1.27.0, `encoding/json`, `encoding/json/v2`, `encoding/xml`, `compress/gzip`, `bufio`, `io`, `net/http`, `httptest`, `testing.B.Loop`, pinned `golang.org/x/perf/cmd/benchstat`.

**Spec:** `docs/superpowers/specs/2026-08-26-go-1.27-modernization-design.md`

## Global Constraints

- Target first-party Go code in the repository root and `src/`; exclude `vendor/`.
- Keep `go 1.27.0`, `-mod=vendor`, module path `threadfin`, and existing application dependencies.
- Workstream 2 lands first and retains ownership of `BenchmarkMapToJSON`, `BenchmarkAPIJSONDecoding`, `BenchmarkUpdateJSONDecoding`, `BenchmarkXMLTVGeneration`, `BenchmarkCachedImageDelivery`, and `BenchmarkSegmentTransfer` in its existing benchmark files. Workstream 4 never redefines or renames them.
- Consume these exact Workstream 2 seams:

```go
func decodeAPIRequest(reader io.Reader) (APIRequestStruct, error)
func decodeServerResponse(reader io.Reader) (ServerResponse, error)
func transferSegment(
	destination io.Writer,
	segment io.ReadCloser,
	beforeWrite func(prefix []byte),
) (inputErr, writeErr error)
```

- Preserve benchmark subnames `{Channel,Configuration}`, `{Small,Large_1MiB}`, `{10Channels_100Programs,100Channels_10000Programs}`, `{32KiB,1MiB}`, and `{188KiB,2MiB,10MiB}`. Do not modify Workstream 2 fixtures between before/after runs.
- Persisted settings, authentication, and updater-state JSON remain two-space-indented. Compact `mapToJSON` retains the existing marshal-failure fallback of `"{}"`.
- `json.DefaultOptionsV1()` comes from `encoding/json`; `UnmarshalRead` comes from `encoding/json/v2`. Do not use v2 defaults.
- Preserve duplicate-name acceptance, invalid UTF-8 replacement, case-insensitive matching, unknown-member handling, nil map/slice behavior, and rejection of empty/trailing-value input.
- Preserve the XML wire shape: `<tv>`, child `<generator>`/`<source>` elements, indented `<channel>`/`<programme>` values, and a final newline. Do not serialize `XMLTV.Generator`/`Source` as root attributes.
- Preserve image delivery as full-body `200` for GET, Range, conditional, and non-GET requests. Do not use `http.ServeContent` or `http.ServeFile`.
- Preserve `bufferingStream`'s early `WriteHeader(200)`. Its later content-type mutation is currently ineffective; successful responses are server-sniffed from body bytes.
- Return or log read, write, flush, close, and publication failures. Never attempt a second status after HTTP commitment.
- Keep Linux (`amd64`, `arm64`, `arm`), FreeBSD (`amd64`, `arm`), macOS (`amd64`, `arm64`), and Windows (`amd64`) working.
- Collect ten same-machine benchmark samples with fixtures outside `b.Loop`. Compare `ns/op`, `B/op`, and `allocs/op`; shared-runner timing is informational. Revert an inconclusive/regressing candidate while retaining contract/benchmark infrastructure.
- Install `benchstat` outside the module at immutable version `golang.org/x/perf/cmd/benchstat@v0.0.0-20260825160852-19be9d8e6c70`.
- Never replace tracked production files from another revision or switch the implementation worktree for baseline collection.
- Do not implement plain+gzip one-pass generation here. Two fixed paths cannot be published as an atomic pair with two renames; rollback retains a mixed-generation/crash window. A generation directory plus one manifest/pointer switch and reader changes requires a separate design. This plan keeps two-pass gzip generation and fixes its current finalization ordering first.
